# 16. Plus 功能

## 这一章能做什么

- 看这台实例的 Plus 状态（Settings 里的徽章）
- 用 Consistency 页扫描项目：重复文案、翻译错位、风格问题、没人引用的词条

## Plus 是什么

Localness 分两档：**免费档**用全部基础功能；**Plus 档**在此之上解锁按实例授权的增强功能。Plus 由一张**license key** 开启——部署方拿到 key 后填进实例的环境变量，重启容器生效。

你不需要为 Plus 做任何配置。没填 key 的实例就是免费档，所有基础功能照常。这一章只讲两件事：怎么确认 Plus 开没开，以及 Plus 解锁的 Consistency 页怎么用。

## 看 Plus 状态

打开左侧栏 **Settings**，滚到 **About** 一节，版本号下方：

| 徽章 | 含义 |
|---|---|
| （没有徽章） | 免费档——实例没有填 license |
| **Plus**（蓝色） | Plus 生效中，显示有效期 |
| **Plus expiring**（黄色） | license 已过期，正在宽限期内，功能仍可用——尽快联系续期 |
| **Plus expired**（黄色） | 宽限期也过了。Plus 功能停止新建和写入；**已有数据不受影响**，照常可读可导出 |

宽限期是 30 天。续期就是让部署方把新 license 填进环境变量、重启容器，徽章会恢复成蓝色。

## Consistency：查重复与翻译问题

侧栏 **Consistency** 入口打开（需要 Plus；免费档会看到功能说明和升级提示）。

页面按四类分区报告，每条发现都有自己的严重度：**红 Error**（用户会看到的错，优先处理）、**黄 Warning**（值得处理的重复）、**灰 Info**（风格建议与提示）。

页面是**左右两栏的评审台**：左栏是按分类分组的发现列表（**分类标题可点击折叠**，含 Error/Warning 的默认展开、只有 Info 的默认收起；每行一条：严重度圆点、key 或原句、语言徽章、Not an issue 按钮），右栏是**选中那条的详情**——源文/译文高亮对照、成员清单，以及 **Resolve** 按钮。列表上方是**筛选条**：按严重度（Error / Warning / Info，可多选）、语言、规则筛选，或按 key / 原文 / 译文搜索；筛了语言后详情里也只显示这些语言的问题。**键盘 ↑ ↓ 换条目、e 把当前条标为 Not an issue**，逐条过报告时不用碰鼠标。每类先显示 20 条，底部 **Show more** 再加载；左栏底部有 **Marked not an issue** 折叠区。

- **Duplicate text**（黄/红）：同一句原文被存成了不同 key。多人协作里最常见：`home.cancel` 和 `settings.cancel` 都是 "Cancel"，翻译做两遍、改文案改两处。**完全相同的那组如果各语言译文已经翻得不一样（比如 ja 一格是「キャンセル」、另一格是「取消」），会标红并显示分歧的语言**——重复已经变成了实际 bug，优先处理。列表行显示原文和 key 数，**选中后右侧看成员**：每个 key、原文、出现在哪些页面、被几个画框引用。`__draft_xxx` 草稿 key 也参与扫描——Capture 生成的占位旁边往往躺着一个内容相同的正式 key
- **Source ↔ translation**（红）：已发布的译文和源文**对不上号**——占位符被改名或丢掉（`{name}` 变成 `{n}`，运行时会显示错数据）、数字丢失或改动（千分位、小数点的本地写法不算，`1,000` 与 `1.000` 视为同一个数；源文本身没有数字时不查，`January` 译成 `1月` 是合法的；key 名这类 `snake_case` 标识符里的数字不算）、URL/邮箱丢失、HTML 标签丢失。**选中条目后右侧**每个语言一行，写明哪个语言缺了或多了什么，并把源文里缺的部分标黄、译文里多的部分标红
- **Lint**（灰）：风格建议——`...` 应写成 `…`、连续空格、中文与英文/数字之间缺空格（只查中文；日文习惯不加空格）、译文结尾标点与源文不符、法语 `!` 前缺窄空格。开关在**项目设置 → Settings → Consistency**（Project Owner 可逐条关）
- **Orphan keys**（灰）：词典里有、但没有任何画框引用的 key——多半是手工建的或设计稿删掉后的残留。数量可能很多，所以整类默认收起；每个 key 一行，可 Resolve（删除）或标为 Not an issue。提示而已：直接建词条不画框是合法用法

### 怎么处理：Resolve 抽屉

点详情顶部的 **Resolve** 打开处置抽屉，**不离开报告页**。左边是这条发现涉及的设计稿截图，每个 key 的画框用不同颜色标出，默认自动放大到这些画框（右上角可切换 Focus / Fit 看整张图），点底部图例只放大那个 key，再点一次回到全部；右边按类型给出处置，**每种处置都是一次点击完成**：

- **Duplicate text → Merge**
  1. **选要保留的 key**：系统按「已发布 > 正式命名（非 `__draft_`）> 画框多 > 已发布语言多 > 更早创建」推荐一个，并写明理由；可以改选
  2. **勾选要并入的 key**：默认全勾。**已发布过的 key 不能被并入**——代码或交付 API 可能还在按这个名字取文案。它旁边有 **Revert to draft** 按钮，确认后撤回发布，再勾选并入
  3. **逐语言确认译文**：保留的 key 缺的语言自动从别的 key 补上（写明来源）；几个 key 译法不一致的语言标黄，必须选一份，默认是保留 key 自己的。源语言永远是保留 key 的原文
  4. 看一眼摘要（移动几个画框、删几个 key），点 **Merge**：画框改绑、发行标签合并、译文补齐、多余 key 删除，一个事务完成。保留 key 若已发布，补进来的译文随之发布
- **Source ↔ translation / Lint → 改译文并发布**：每个出问题的语言一个输入框，预填当前已发布译文；边改边重新检查，通过就变绿。Lint 能自动修的（省略号、连续空格、中文与英文间距、法语窄空格）有 **Auto-fix**，先给出前后对比再应用。点 **Save & publish {语言}** 只改这一种语言、**改完直接发布**，下次扫描该条即消失；仍未通过检查也允许保存，会提示
- **Orphan keys → Delete key**：删除词条及其所有语言。已发布的同样要先 **Revert to draft**

抽屉底部始终有 **Not an issue**、**Open in Translations**（单 key 问题按 key 名搜、重复问题按原文搜；本次访问显示全部发行、状态和日期，带 Restore 横幅，你保存的筛选不会被改，刷新页面仍保持）和 **Open in Editor**（直落当前截图上的画框；若页面或这个框被发行筛选隐藏，会临时放宽为全部发行）作为退路。关闭抽屉后报告自动刷新。

### Not an issue 与恢复

不是问题的发现点 **Not an issue**，它会收进页底的 **Marked not an issue** 折叠区；点 **Restore** 放回列表。**它不是永久隐藏**：同一组之后出现了新成员会自动重新冒出来——标记只对你见过的那批 key 生效，不会把后来新产生的重复一起吞掉。翻译错位与 Lint 同理：这条词条**任何语言的已发布译文一改**，标记即失效、重新检查。

### 扫不出来什么

- **还没发布的**：翻译错位和 Lint 只查**已发布**文案；只改了草稿的不报
- **意思一样、写法不同的**：`Save` 和 `保存进度` 不会成组——Consistency 管写法雷同，不管语义
- **设计稿改了文案、平台还没改的**：那是 Capture 导入时的对照提示（第 8 章），不是这里
