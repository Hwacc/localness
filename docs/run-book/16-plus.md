# 16. Plus 功能

## 这一章能做什么

- 看这台实例的 Plus 状态（Settings 里的徽章）
- 用 Consistency 页扫描项目：重复文案、翻译错位、风格问题、没人引用的词条

## Plus 是什么

Localness 分两档：**免费档**用全部基础功能；**Plus 档**在此之上解锁按实例授权的增强功能。Plus 由一张**license key** 开启——部署方拿到 key 后填进实例的环境变量，重启容器生效。

你不需要为 Plus 做任何配置。没填 key 的实例就是免费档，所有基础功能照常。这一章只讲两件事：怎么确认 Plus 开没开，以及 Plus 解锁的 Consistency 页怎么用。

## 看 Plus 状态

打开左侧栏 **Settings**，滚到 **About** 一节，版本号下方：

| 徽章 | 含义 |
|---|---|
| （没有徽章） | 免费档——实例没有填 license |
| **Plus**（蓝色） | Plus 生效中，显示有效期 |
| **Plus expiring**（黄色） | license 已过期，正在宽限期内，功能仍可用——尽快联系续期 |
| **Plus expired**（黄色） | 宽限期也过了。Plus 功能停止新建和写入；**已有数据不受影响**，照常可读可导出 |

宽限期是 30 天。续期就是让部署方把新 license 填进环境变量、重启容器，徽章会恢复成蓝色。

## Consistency：查重复与翻译问题

侧栏 **Consistency** 入口打开（需要 Plus；免费档会看到功能说明和升级提示）。

**扫描在后台进行，结果会保存**：打开页面直接显示上次扫描的结果，不用等。之后词条、译文、画框或 Consistency 设置有变化，右上角显示 **Outdated**，同时自动在后台重扫，旁边显示进度（Checking rules 3/11），扫完自动换上新结果，扫描期间页面照常可用。右上角还显示上次扫描的时间，**Re-check** 手动重扫。项目第一次打开时还没有结果，页面显示扫描进度。扫描失败时显示 **Scan failed**（悬停看原因），点 Re-check 或 Retry 重试；失败后不会自动重扫。

页面按四类分区报告，每个分类标题前的图标表示这类看什么（悬停有说明，摘要下方有图例）：

- 📖 **Every key**（Duplicate text、Orphan keys）：查词典结构，**所有 key 都看**，不论发布与否，自动 key 也算。比较的是线上原文；从没发布过的 key 用草稿
- 👁 **Published only**（Source ↔ translation、Lint）：查用户看得到的文案，**只看已发布**；只改了草稿的不查

成员卡片上的徽章说明 key 的状态：**Auto key**（没起 key 名的框自动生成的 `__draft_…` key，发布前要改成正式名）、**Unpublished**（正式 key 但从没发布过）、**Pending edit**（源文有未发布的修改，卡片原文下方以「→ “…”」显示新措辞，发布前不参与检查）。已发布且没有待发布修改的 key 不显示徽章。

每条发现都有自己的严重度：**红 Error**（用户会看到的错，优先处理）、**黄 Warning**（值得处理的重复）、**灰 Info**（风格建议与提示）。

页面是**左右两栏的评审台**：左栏是按分类分组的发现列表（**分类标题可点击折叠**，含 Error/Warning 的默认展开、只有 Info 的默认收起；每行一条：严重度圆点、key 或原句、语言徽章、Not an issue 按钮），右栏是**选中那条的详情**——源文/译文高亮对照、成员清单，以及 **Resolve** 按钮。列表上方是**筛选条**：按严重度（Error / Warning / Info，可多选）、语言、规则筛选，或按 key / 原文 / 译文搜索；筛了语言后详情里也只显示这些语言的问题。**键盘 ↑ ↓ 换条目、e 把当前条标为 Not an issue**，逐条过报告时不用碰鼠标。筛选和搜索都在服务端完成（搜索输入停顿约 0.3 秒后才查询），严重度按钮上的数字始终是未筛选的总数，筛选生效时摘要显示「命中/总数 shown」。每类内按严重度 → 规则 → key 排序，先显示 20 条，底部 **Show more** 再取下一页；键盘 ↓ 走到某类已加载的最后一条时会自动取下一页。重扫或修复后刷新会保留你已展开的条数。左栏底部有 **Marked not an issue** 折叠区，首次展开时才加载。

- **Duplicate text**（黄/红）：同一句原文被存成了不同 key。多人协作里最常见：`home.cancel` 和 `settings.cancel` 都是 "Cancel"，翻译做两遍、改文案改两处。**完全相同的那组如果各语言译文已经翻得不一样（比如 ja 一格是「キャンセル」、另一格是「取消」），会标红并显示分歧的语言**——重复已经变成了实际 bug，优先处理。列表行显示原文和 key 数，**选中后右侧看成员**：每个 key、原文、出现在哪些页面、被几个画框引用。`__draft_xxx` 草稿 key 也参与扫描——Capture 生成的占位旁边往往躺着一个内容相同的正式 key
- **Source ↔ translation**（红）：已发布的译文和源文**对不上号**——占位符被改名或丢掉（`{name}` 变成 `{n}`，运行时会显示错数据）、数字丢失或改动（千分位、小数点的本地写法不算，`1,000` 与 `1.000` 视为同一个数；源文本身没有数字时不查，`January` 译成 `1月` 是合法的；key 名这类 `snake_case` 标识符里的数字不算）、vue-i18n 链接消息 `@:common.save` 或 i18next 嵌套 `$t(common.save)` 指向的 key 被改（`@.lower:` 这类大小写修饰符、`$t()` 的参数各语言可以不同；列表占位符 `{0}` 也算占位符）、URL/邮箱丢失、标签丢失或没闭合（HTML `<b>`、富文本组件 `<bold>…</bold>`、react-i18next `Trans` 的序号标签 `<0>…</0>` / `<1/>`、空标签 `<>…</>`；开、闭、自闭合分开计数，顺序可以不同；序号标签里的数字不算进 Numbers）。**复数**：ICU `{n, plural, …}` 和 vue-i18n 竖线分支 `one file | {n} files` 各语言分支数不同，只看用了哪些占位符、不看次数（字面竖线写作 `{'|'}`）；i18next 的 `items_one` / `items_other` / `items_few` 这类同名前缀 key（须有 `_other`）当作一族：`{{count}}` 各形式可有可无，某形式用了族里其他形式源文才有的占位符也算正常；源语言没有的形式（如 ru 的 `_few`）对照 `_other` 的源文检查，详情里源文旁注明「from items_other」。**选中条目后右侧**每个语言一行，写明哪个语言缺了或多了什么，并把源文里缺的部分标黄、译文里多的部分标红
- **Lint**（灰）：风格建议——`...` 应写成 `…`、连续空格、中文与英文/数字之间缺空格（只查中文；日文习惯不加空格）、译文结尾标点与源文不符、法语 `!` 前缺窄空格。开关见下方「项目设置」
- **Orphan keys**（灰）：词典里有、但没有任何画框引用的 key——多半是手工建的或设计稿删掉后的残留。数量可能很多，所以整类默认收起；每个 key 一行，可 Resolve（删除）或标为 Not an issue。提示而已：直接建词条不画框是合法用法。i18next 复数族里只要有一个形式绑了画框，其余形式就不报

**项目设置 → Consistency** 标签页（Project Owner；新建项目时没有，建好后再设）：
- **Message syntax**：项目用哪个 i18n 运行时。**Auto**（默认）同时认 vue-i18n、i18next、ICU、printf，适合 ICU（FormatJS、i18next-icu）或混用的项目；**vue-i18n** 认 `{name}` / `{0}`、`@:key`、竖线复数，`{{name}}`、`$t()`、`_one`/`_other` 当普通文字；**i18next** 认 `{{name}}`、嵌套 `$t(key)`、`_one`/`_other` 复数族，`{name}`、`@:key`、竖线当普通文字。选对了能少掉另一种语法造成的误报（例如 i18next 项目里字面的 `{name}`、vue 项目里碰巧叫 `step_one` / `step_other` 的 key）。printf 和标签所有选项都认
- **Numbers**：Error（默认）/ Warning / Off。日期、序号在各语言写法常不同，嫌吵可降级或关掉；Off 时扫描和 Resolve 里的实时检查都不再报
- **Lint rules**：逐条开关

### 怎么处理：Resolve 抽屉

点详情顶部的 **Resolve** 打开处置抽屉，**不离开报告页**。左边是这条发现涉及的设计稿截图，每个 key 的画框用不同颜色标出，默认自动放大到这些画框（右上角可切换 Focus / Fit 看整张图），点底部图例只放大那个 key，再点一次回到全部；右边按类型给出处置，**每种处置都是一次点击完成**：

- **Duplicate text → Merge**
  1. **选要保留的 key**：系统按「已发布 > 正式命名（非 `__draft_`）> 画框多 > 已发布语言多 > 更早创建」推荐一个，并写明理由；可以改选
  2. **勾选要并入的 key**：默认全勾。**已发布过的 key 不能被并入**——代码或交付 API 可能还在按这个名字取文案。它旁边有 **Revert to draft** 按钮，确认后撤回发布，再勾选并入
  3. **逐语言确认译文**：保留的 key 缺的语言自动从别的 key 补上（写明来源）；几个 key 译法不一致的语言标黄，必须选一份，默认是保留 key 自己的。源语言永远是保留 key 的原文
  4. 看一眼摘要（移动几个画框、删几个 key），点 **Merge**：画框改绑、发行标签合并、译文补齐、多余 key 删除，一个事务完成。保留 key 若已发布，补进来的译文随之发布
- **Source ↔ translation / Lint → 改译文并发布**：每个出问题的语言一个输入框，预填当前已发布译文；边改边重新检查，通过就变绿。Lint 能自动修的（省略号、连续空格、中文与英文间距、法语窄空格）有 **Auto-fix**，先给出前后对比再应用。Source ↔ translation 只在**一换一**时有 Auto-fix：译文里错的和缺的数量相同、类型相同（占位符改名 `{n}`→`{name}`、链接消息 key 改错、URL/邮箱被改、标签名写错 `<b>`→`<bold>`，开闭一起换），按顺序原位替换，复数分支里每个分支都换；算出的结果必须通过该规则复查才会出现按钮。纯缺失（缺了得插到哪是语言问题）、类型不同、Numbers 都要手改。点 **Save & publish {语言}** 只改这一种语言、**改完直接发布**，下次扫描该条即消失；仍未通过检查也允许保存，会提示。改的是**源语言**且措辞真的变了（只改空白不算）时，输入框下会提示「Saving marks N other languages of this key as Outdated」——N 只数当前还是最新、且有译文的语言；key 仍是草稿时不提示
- **Orphan keys → Delete key**：删除词条及其所有语言。已发布的同样要先 **Revert to draft**

抽屉底部始终有 **Not an issue**、**Open in Translations**（单 key 问题按 key 名搜、重复问题按原文搜；本次访问显示全部发行、状态和日期，带 Restore 横幅，你保存的筛选不会被改，刷新页面仍保持）和 **Open in Editor**（直落当前截图上的画框；若页面或这个框被发行筛选隐藏，会临时放宽为全部发行）作为退路。关闭抽屉后，若做过修改，这条先从列表移除，并立刻复查改过的 key（连同 i18next 复数族的兄弟 key）：翻译错位、Lint、Orphan 这类单 key 问题马上更新，没真正解决的当即重新出现；涉及这些 key 的重复组先隐藏，等随后的后台重扫重新判定。

### Not an issue 与恢复

不是问题的发现点 **Not an issue**，它会收进页底的 **Marked not an issue** 折叠区；点 **Restore** 放回列表。标记只改白名单，不会触发重扫。**它不是永久隐藏**：同一组之后出现了新成员会自动重新冒出来——标记只对你见过的那批 key 生效，不会把后来新产生的重复一起吞掉。翻译错位与 Lint 同理：这条词条**任何语言的已发布译文一改**，标记即失效、重新检查。

### 扫不出来什么

- **还没发布的**：翻译错位和 Lint 只查**已发布**文案；只改了草稿的不报。重复和孤儿按 key 的**线上原文**判定——发布过的看已发布源文，从没发布过的（含 `__draft_`）看草稿。已发布 key 上还没发布的源文修改不参与判定，卡片上以「Pending edit: “…”」单独显示
- **意思一样、写法不同的**：`Save` 和 `保存进度` 不会成组——Consistency 管写法雷同，不管语义
- **设计稿改了文案、平台还没改的**：那是 Capture 导入时的对照提示（第 8 章），不是这里
