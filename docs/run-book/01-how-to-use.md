# 1. 这份手册怎么用

这本手册覆盖 Localness 的全部界面操作：上传截图、画框、填译文、发布、导出、和公司 Git 仓对账，以及给 CI 或 MCP 配只读访问。对应 0.3.x。

## 你要做的事在哪一章

| 要做的事 | 读 |
|---|---|
| 上传截图、画框、OCR、填译文、发布、导出 | 第 8–10 章 |
| 建项目，配 OCR 和 key 命名规范 | 第 6 章 |
| 建发行标签，按发行筛选和导出 | 第 7 章 |
| 词条表：批量发布、撤回、删除、Copy / Move 到别的项目 | 第 9 章 |
| 邀请人进队、发邀请码、改角色 | 第 5 章 |
| 和公司 Git 仓对账：Pull / Push / 冲突 | 第 11 章 |
| 给 CI、MCP 或 agent 配只读访问 | 第 12 章 |
| 查某个动作谁能做 | 第 14 章 |

第一次用，先读第 2 章和第 4 章：第 2 章讲 Localness 是什么、一条主路径怎么走完，第 4 章讲侧栏每个入口去哪、当前项目在哪切换。读完再回这张表。

## 角色

队员是基准：能看见本队全部项目，画框、填译文、发布、导出、Pull / Push 都能做，自己也能建项目（建完自己就是那个项目的管家）。管家和队长在队员之上各多管一些事，Admin 是账号级别的身份，调用方不进界面：

| 手册里写 | 界面上是 | 比队员多管什么 |
|---|---|---|
| 管家 | Project Owner | 项目设置（OCR、源语言、key 命名规范）、发行标签的增删改名、Git 绑定、删 API token |
| 队长 | Team Owner | 邀请码、按人邀请、队内角色变更、删团队 |
| Admin | Admin | 建团队；项目没有管家时，由他任命管家 |
| 调用方 | — | 不进界面，用 API token 取已发布文案 |

Admin 在 **Teams** 页的队伍详情里显示为一个徽标，和 Team Owner / Team Member 并排。它不是队伍角色：一个 Admin 如果不在某个团队里，他对那个团队的项目什么也做不了。

**队长不等于管家。** 建项目的人自动成为该项目的管家，队长不会因为是队长就成了管家；队长要用管家权限，得被任命成管家。这条在第 6 章和第 14 章会反复用到。

## 三种「草稿」，先分清

后面每章都会碰到 Draft 这个词，它在三个地方含义不同：

- **Draft / Published** 是词条的发布状态，显示在词条表的 **Status** 列。从未发布过，或任一语言的草稿与已发布不一致，就是 Draft。
- 词条表筛选器里的 **All statuses / Draft / Published** 只决定表格显示哪些行，不改任何东西。
- `__draft_…` 是编辑器给还没命名的框自动建的占位 key，界面上显示成 `__draft_` 加 5 位短哈希。词条表默认把它们一并列出来，不想看就取消勾 **Show __draft_ keys**；导出时选 key 的那张表相反，默认不列，勾上才有。

导出和对外 API 永远只取已发布文案，草稿取不到。
